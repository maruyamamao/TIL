## OR(Oparetions Research： オペレーションズリサーチ)
→ システムの作業計画・管理などにおいて統計科学技術や統計手法を用いて問題の最適な解決策を見つけ、経営に関する意思決定を支援するもの

### 線形計画法(LP： Linear Programming)
→ 与えられた条件から最大の効果を得るための解を求めるときに用いられる技法

```html:例
原料A、Bを使って製品X、Yを製造販売する場合の最大利益を求める

[制約条件]
・製品Xは原料Aを6kg/個、原料Bを2kg/個使用して製造
・製品Yは原料Aを3kg/個、原料Bを4kg/個使用して製造
・製品Xは30万円/個、製品Yは40万円/個の利益が得られる
・原料Aは120kg、原料Bは100kgしか使用できない

1. 製品Xの製造量をx、製品Yの製造量をyとして、制約条件式と目的関数(利益を求める式)を導き出す
　　[制約条件式]  6x + 3y <= 120  ・・・ 原料A
                 2x + 4y <= 100　・・・ 原料B
                 x >= 0, y >= 0　・・・ 製造量は0以上の整数
    [目的関数]   利益 = 30x + 40y ・・・ 最大にする
    
2. 制約条件式から、xとyを求める
　　x <= 10, y <= 20
  
3. 目的関数のxとyにそれぞれ最大値を代入して、最大利益を求める
   最大利益 = 30万円/個 × 10個 + 40万円/個 × 20個 = 1,100万円
```

### 日程計画法
→ 作業などのスケジュールを立案すること
- **PERT**(Program Evaluation and Review Technique)
→ 作業期間を見積もるために計画を立案
- **CPM**(Critical Path Method)
→ 最小コストでの日程短縮も視野に入れて計画を立案する

#### アローダイアグラム
→ 先行作業をもとに各作業の流れを矢電で表した図、PERT図ともいわれる
##### 最早結合点時刻
→ 結合点において最も早く作業を開始できる時刻
→ 出発点である結合点1を0として、各作業の所要日数を加算していく全身計算で求める
→ 結合点に至る経路が複数ある場合は、最も多い加算結果が最早結合点時刻となる

##### 最遅結合点時刻
→ プロジェクトの最短所要日数の範囲で、結合点において最も遅く作業を開始できる時刻
→ 最終結合点(到達点)の最早結合点時刻から各作業の所要日数を減算していく後退計算
→ 結合点に至る経路が複数ある場合は、最も小さい減算結果が最遅結合点時刻となる
→ 各結合点における余裕日数(**スラック**)が最遅結合点時刻 - 最早結合点時刻

![アローダイアグラムの図](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/3540632/41031f6a-2d36-4b48-9a72-07d62d5c4eb9.png)


##### クリティカルパス
→ スラックが0(最遅結合点時刻 = 最早結合点時刻)の結合点を結んだ、作業日数に余裕のない経路
→ 作業に遅れが発生すると、全体の作業日程に遅れが生じるため、重点的に管理する必要がある
- **クラッシング**
→人員やコストなどを追加投入して、作業日程を短縮する方法
- **ファストトラッキング**
→特定作業の細分化/並行化や、先行工程が終了する前に次の工程を並行して進めることなどによって、作業日程を短縮する方法

#### ガントチャート
→ 日程管理を行うために用いられる図
→ 作業予定(計画)期間と実際の作業期間を上下に、その長さを横棒(バー)で書き込む
→ 作業の進捗状況は把握しやすい、作業の前後関係などについては把握できない
